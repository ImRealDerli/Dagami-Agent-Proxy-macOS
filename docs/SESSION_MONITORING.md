# Состояние сессий и лимиты

Откройте «Главная → Сессии». Для новых запусков через Dagami карточка показывает состояние клиента, модель и доступные лимиты. Контекст разговора отображается отдельно от квоты аккаунта. Если клиент не передал данные, программа пишет об этом, а не подставляет ноль.

Мониторинг можно отключить в настройках. Dagami сохраняет только состояние, название модели, числовые счётчики и время. Тексты запросов, ответы, аргументы инструментов и токены входа в файлы мониторинга не записываются. Данные хранятся локально с доступом текущему пользователю и удаляются вместе с управляемой сессией.

## CLI

Antigravity CLI и Claude Code передают доступные сведения через statusline и штатные hooks. Дополнительные настройки действуют только при запуске через Dagami. Поддержка флагов проверяется перед запуском; старый клиент запускается без неподдерживаемых параметров.

Для Codex доступны пассивные hooks. Если Codex просит доверие, проверьте их командой `/hooks`. Dagami не подтверждает доверие автоматически. Лимиты читаются через `account/rateLimits/read` в отдельном локальном `codex app-server`: без создания разговора и отправки запроса модели. Этот интерфейс помечен OpenAI как экспериментальный.

Источники: [Antigravity statusline](https://antigravity.google/docs/cli/statusline/), [Claude statusline](https://code.claude.com/docs/en/statusline), [Codex app-server](https://developers.openai.com/codex/app-server), [Codex hooks](https://learn.chatgpt.com/docs/hooks).

## Antigravity App и IDE

Для событий работы нажмите «Подключить» в настройках мониторинга или в карточке сессии. Затем перезапустите приложение через Dagami. Добавляется отдельная группа штатных hooks в `~/.gemini/config/hooks.json`. Чужие правила сохраняются. При отключении удаляются только неизменённые правила Dagami; ручные изменения требуют отдельного решения пользователя. Hooks сообщают о событиях, не меняют аргументы инструментов и не разрешают действия агента.

[Документация Antigravity hooks](https://antigravity.google/docs/hooks/).

Квоты App/IDE считываются у локального language server выбранной управляемой сессии. Проверяются пользователь процесса и принадлежность к этой сессии, используются только loopback-порты. Временный CSRF-маркер нужен для локального IPC и не является токеном Google. Для локального TLS закрепляется сертификат процесса; проверка внешних сертификатов сохраняется.

Для понимания протокола изучен [Quotty](https://github.com/confeden/Quotty). Его GPL-3.0 код не включён в MIT-проект: macOS-реализация написана отдельно. `RetrieveUserQuotaSummary` и `GetUserStatus` — внутренние интерфейсы Antigravity, а не публичный Google API. Их формат может измениться; официальная поддержка этого способа и юридическая гарантия не заявляются. При несовместимости карточка покажет ошибку. Общий или отдельно запущенный backend, не принадлежащий выбранной сессии, автоматически не выбирается.

Чтение квот выполняется при открытой вкладке сессий не чаще одного раза в две минуты на сессию; есть ручное обновление. Это не проверка подписки или права доступа к сервису и не способ изменить лимиты либо обойти их.

## Проверка сборки

Тесты используют временные файлы, фикстуры и loopback. Живые аккаунты, их квоты, системный DNS и пользовательские настройки hooks при сборочной проверке не изменяются. Получение настоящих квот зависит от установленной версии клиента и его действующей авторизации.
