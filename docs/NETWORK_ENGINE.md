# Rust-транспорт mac.28

Исходящие TCP/TLS-соединения моста перенесены в отдельный процесс на Tokio/rustls. Профили, Keychain, маршруты, DNS, HTTP CONNECT и SOCKS5 остаются под управлением Python; он передаёт байты выбранному транспорту. Интерфейс приложения не переписан. Совместимый Python-транспорт сохранён для запуска исходников без нативного помощника.

## Что меняется

- Один TLS-контекст на процесс транспорта, а не новый контекст на каждое соединение.
- Асинхронная передача в обе стороны, ограниченные буферы и корректное завершение half-close. В совместимом Python-транспорте обращения к одному SSL-сокету сериализованы, ожидание сети выполняется вне блокировки.
- IPv6/IPv4 пробуются с задержкой 200 мс, одновременно не более трёх адресов. Один адрес ожидается до трёх секунд; общий срок TCP/TLS задаёт мост, обычно восемь секунд.
- HTTP CONNECT можно повторить один раз после разрыва или 502/503/504 до отправки клиентских данных. 407 не повторяется; запросы модели после открытия туннеля не переигрываются.
- SOCKS5 использует IDNA, IPv4 и IPv6 в соответствующем формате, проверяет версии и длину реквизитов. HTTP CONNECT учитывает промежуточные ответы и IPv6 authority.
- Smart DNS хранит несколько адресов, откладывает отказавшие, объединяет одновременные DNS-запросы одного имени и временно ставит неработающий выбранный узел в резерв. Свежий адрес самого DNS-провайдера остаётся резервом после seed-адресов. Другие провайдеры автоматически не добавляются.
- Если выбранное DNS-реле сразу закрывает поток или возвращает ранний TLS alert, его адрес временно исключается для следующего подключения. Открытая TLS-сессия не переносится на другой сервер.

Экспериментальное дробление 1/8/32 байта сохранено в нативном слое: оно ограничивает размер первых 4 КиБ TCP-записей. По умолчанию отключено; ядро ОС может объединять записи, поэтому обход DPI не гарантируется. Для долгих ответов включён TCP keepalive, без искусственного ограничения длительности ответа модели.

## Границы доступа

Rust не слушает публичный TCP-порт. Он принимает управляющие запросы через Unix-сокет в случайном каталоге с правами 0700; сам сокет имеет 0600, проверяется UID клиента. В запросе открытия передаются только адрес, порт, режим TLS и тайм-аут. Пароли прокси остаются в Keychain и в штатном авторизационном обмене, в аргументы процесса и журнал не записываются.

Проверка сертификатов и имени сервера обязательна. Используется CA-файл, выбранный Python/приложением; при его отсутствии — Mozilla roots. Сертификаты перехвата не устанавливаются. После уже подтверждённого рукопожатия закрытие TLS без close_notify трактуется как EOF, совместимо с прежним SSLSocket; неверные сертификаты и повреждённые TLS-записи по-прежнему отклоняются. Длины HTTP-сообщений и внутренний TLS проверяются соответствующим протоколом/клиентом.

Для сетевого процесса мягкий лимит дескрипторов повышается до 1024, если разрешает существующий hard limit. Настройки launchd и sysctl не меняются. Это позволяет обслуживать заявленный бюджет соединений при штатном GUI-лимите macOS в 256 дескрипторов; отказ изменения не мешает запуску.

На процесс транспорта — два асинхронных worker и максимум 128 активных соединений. Прекращение управляющего stdin завершает помощник и его соединения; остановка не требует изменения системной сети. ОС DNS, /etc/hosts и фильтры пользователя при этом не переписываются.

Для нового транспорта перезапустите приложения через обновлённый Dagami. Запущенная ранее сессия продолжает использовать свой прежний движок. Действующий движок указан в настройках и подробностях новых сессий.

Отказ upstream, неверный пароль, ограничения его выходного IP и игнорирование proxy-настроек самим клиентом требуют отдельного решения. Rust-транспорт не меняет регион сервера, подписку или квоту. Клиенты без поддержки proxy-env/параметров запуска всё ещё требуют отдельного адаптера; системный TUN в этой версии не добавлен.

## Изученные источники

[Официальный Dagami 0.4.1](https://github.com/j46871417-ui/Dagami-Agent-Proxy/releases/tag/v0.4.1-beta) остаётся последним проверенным upstream. [Antigravity CLI Unlocker](https://github.com/NakishN/antigravity-cli-unlocker) использует обновление адресов релеев и проверку пути; его код и системный hosts-пин не включались. Неизвестные бинарные сигнатуры приложений не изменялись.

[CPython](https://github.com/python/cpython/issues/151508) описывает риск одновременного чтения/записи одного SSLSocket. Нативная реализация использует [Tokio/rustls](https://docs.rs/tokio-rustls/latest/tokio_rustls/client/struct.TlsConnector.html). Лицензии зависимостей включены в APP.
