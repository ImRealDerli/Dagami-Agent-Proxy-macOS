> mac.6: «Добавить профиль → Smart DNS без прокси → Все ИИ». Можно выбрать DNS-провайдера и добавить свои домены, включая *.example.com. Старый DNS-профиль можно переключить на «Все ИИ» через «Изменить профиль». Маршрут действует для приложений, запущенных через Dagami; системный DNS не меняется. Доступность всех сервисов не гарантируется одним DNS.

> mac.5: «Добавить профиль → Smart DNS без прокси». Задайте имя, выберите провайдера или впишите DNS endpoints, сохраните и запустите приложение через Dagami. Smart DNS применяется к списку Google/Antigravity; доступность зависит от провайдера и сети и не гарантирует обход любого ограничения. Настройки DNS всей macOS автоматически не меняются.

> mac.4: исправлена проверка TLS внутри HTTPS-прокси; ошибки проверки содержат адрес и конкретную причину. Ошибка 503 удалённого сервера не считается успехом.

> mac.3: исправлен выбор записи пароля в Keychain. Новые записи используют фиксированный account; старые профили сохраняют совместимость. При ошибке подтверждения в mac.2 откройте mac.3 и повторно сохраните полную ссылку.

> Обновление mac.2: «Добавить прокси» и «Изменить прокси» принимают полную ссылку. Протокол, адрес, порт и реквизиты заполняются вместе; Keychain проверяется чтением после записи. Новая версия отмечена в заголовке окна.

> Обновление mac.1: кнопка «Логин / пароль прокси» меняет реквизиты выбранного профиля. Пароль вводится буквально, без URL-кодирования. Перед открытием новой .app полностью закройте прежнюю копию через меню выхода.

## Запуск

1. Откройте `Dagami Agent Proxy.app` рядом с этой инструкцией либо скопируйте весь bundle в `~/Applications`.
2. При первом ручном запуске введите свой ключ из @bright26bot. Формат и проверка совпадают с Windows. Ключ и proxy-пароли сохраняются в Keychain через Security.framework; они не передаются аргументами системных команд.
3. Выберите upstream-прокси либо создайте профиль `direct://` для сети macOS / системного VPN.
4. Кнопка «Маршрут / Smart DNS» открывает DNS endpoints, импорт .mobileconfig, проверки, блокировку обновлений и экспериментальное разделение TLS. Два флага на главном экране управляют прокси и Smart DNS. Выключение upstream сохраняет адрес и пароль.
5. Выберите приложение и нажмите «Запустить». Для обычного открытия через Finder создайте управляемый запуск. Копии ярлыков находятся в `~/Applications/Dagami Agent Proxy`.
6. Для Google-входа начните вход внутри Antigravity, затем «Ещё → Вход Google через прокси». Можно найти свежую ссылку в журналах двух вариантов IDE, вставить её вручную, скопировать и выбрать аккаунт. Требуется Chrome, Chromium, Edge либо Brave.

Автозапуск использует пользовательский LaunchAgent. Неактивированная копия не показывает окно активации при входе в систему. Главное окно не требует root; запись системного DNS запрашивает права отдельно.

## Подготовка Antigravity

«Ещё → Подготовить backend Antigravity» проверяет все восемь известных protobuf-сигнатур и proxy-переменные, создаёт приватную копию всего `.app` в `~/.devproxy/prepared-macos`, изменяет только её и проверяет ad-hoc подпись. Установленный оригинал не изменяется. При неизвестных или частичных сигнатурах операция отклоняется. Для копии нужно примерно 0.5–1 ГБ свободного места.

Это экспериментальная функция: полный запуск подписанной копии, Google-вход и доступ к модели в этой среде не проверены. Подготовка может быть отклонена macOS или политикой приложения. Региональная машинная инструкция Windows CLI не переносится на неизвестный Mach-O; для неподтверждённой CLI используется обычный управляемый запуск.

«Отменить подготовку» возвращает запуск к оригиналу и восстанавливает созданные ярлыки. Повреждение SHA-256 не объявляется успешным откатом. Сначала остановите сессию. Обновление оригинальной IDE требует отката и повторной подготовки.

## Маршруты

Smart DNS работает только для точного списка Google/Antigravity из Windows-кода. DNS-only оставляет accounts.google.com обычной сети macOS. Другие адреса идут через upstream либо прямую сеть по выбранному флагу. Неудача Smart DNS до открытия туннеля допускает резерв через настроенный upstream; отказ upstream не приводит к скрытому прямому подключению. TLS не расшифровывается, проверка сертификатов сохраняется.

Провайдеры: Dagami → MagicDNS по умолчанию; Comss.one, GeoHide, Malw.link и Xbox DNS — по явному выбору. Есть собственные HTTPS/DoT/UDP/TCP endpoints, TTL-кэш, резервные адреса и EDNS0 padding с размером UDP 1232. Импорт поддерживает XML/binary plist .mobileconfig; CMS-подписанный профиль нужно предварительно экспортировать в plist. Импорт читает DNSSettings, не устанавливает профиль macOS.

«DNS в системе» — отдельный существующий механизм networksetup и /etc/resolver с копиями и откатом. Он принимает IP DNS-сервера. Это не Windows DNS-служба и не установка DoH/DoT в систему; настройки шифрованных endpoints применяются к мосту управляемых приложений. Реквизиты upstream не меняют транспорт системного resolver macOS.

Перед изменением маршрута показывается список сессий и запрос их закрытия. Сохранение происходит после подтверждения остановки; отказ и ошибка оставляют профиль прежним. Явная остановка завершает процессную группу с дочерними процессами. Приложения, самостоятельно создающие новую сессию ОС/daemon, могут потребовать отдельного адаптера.

## Отличия от Windows и границы проверки

- WinForms заменён Tk-интерфейсом macOS; внешний вид не является копией Windows.
- winws.exe / goodbyedpi.exe, Windows UAC/Low Integrity и Планировщик задач не исполняются на macOS. Есть собственный LaunchAgent, отдельный запрос DNS-прав и экспериментальное дробление отправки TLS в мосте. TCP может объединять записи: эффект дробления зависит от сети.
- Встроенный Windows-установщик обновлений, Windows DNS-служба и машинный патч CLI PE/x64 не перенесены. Новую Mac-сборку устанавливают заменой всего .app.
- Ссылки поддержки открываются в браузере; Windows-форма загрузки баг-репорта заменена доступом к существующему сайту поддержки.
- Новый ручной адаптер использует HTTP(S)-окружение. Приложение, игнорирующее proxy-env, не становится совместимым автоматически.
- Тесты на фикстурах не доказывают вход в аккаунт, наличие подписки, допустимый регион API, квоту или ответ модели.
- В среде сборки запрещены список процессов, loopback-сокеты и доступ к WindowServer. Проверка GUI прервалась, полноценные сетевые тесты не прошли из-за ограничений среды. Смотрите `Verification` рядом с Source.
- Нет Developer ID/notarization. Сборка подписана локально ad-hoc. Для распространения требуется собственная подпись разработчика; не отключайте защиту macOS целиком.

## CLI и пересборка

CLI принимает тот же файл: `Dagami Agent Proxy.app/Contents/MacOS/Dagami Agent Proxy`.
Стандартные команды: `--help`, `--permissions-info`, `profile`, `apps list`, `run`, `sessions`, `stop`, `patch`, `unpatch`, `login`, `dns`, `autostart`.
Подготовка backend: `backend prepare antigravity`, `backend status antigravity`, `backend restore antigravity`.

Для пересборки на Intel Mac нужен Python 3.12 с Tk и зависимости `.[build,desktop]`:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install '.[build,desktop]'
.venv/bin/python tools/build_portable.py
```

`--skip-gui-smoke` предназначен только для среды без WindowServer и оставляет GUI непроверенным.
Архив создаётся со всеми библиотеками, ресурсами и символическими ссылками bundle.
На Apple Silicon нужна отдельная нативная сборка; этот результат проверяет только состав Intel-артефакта.
